# 愿景：太阳系上的束递网

**DTN 萤火束递网（Yinghuo）** 所对应的远期图景，不是单机演示或实验室拓扑，而是：**太阳系里到处都有这样的系统在跑**——行星、卫星、中继站、深空探测器、地面站与在轨设施，各自持有局部接触与保管能力，在链路断续、时延巨大的环境里，把报文一批批递下去。

## 问题空间

日地月、行星际乃至更远的航迹上，通信天然不连续：

- 相对运动与遮挡使接触窗口周期性出现又消失；
- 光速时延从近地秒级，到火星分钟级，再到更远任务可达数十分钟；
- 节点可能长期无法与目的端同时在线，更无法依赖端到端实时会话。

在这种约束下，「先连上再传完」的互联网假设不再成立。需要的是：**有窗则传，无窗则存；能近则近，不能近则交给下一跳。**

## 运行图景

想象若干年后的常态：

- **地面与近地**：任务中心、深空网天线、近地中继星座，各自运行束递节点，按接触计划或动态图交换保管中的束；
- **行星与卫星**：着陆器、轨道器、伴飞器在本地保管科学数据与指令，待对地或对中继窗口打开再转发；
- **航迹上的飞行器**：巡航段长时间离线，仍持续产生遥测与载荷数据，并在途经中继或进入接触弧时交班；
- **多任务并存**：不同机构、不同任务相位的节点彼此不要求全网一致视图，只要求在相遇时交换足够的摘要与下一跳决策依据。

商业上不必由一家公司拥有整张网。每一台中继可以是独立计价的微节点，锚点开放注册，束按接触与约束选路，过路保管与转发按跳结算——见 [`market.md`](./market.md)。

「到处都在跑」并不意味着一张全球同步的超级路由表，而是：**无数局部萤火式的节点，在间歇相遇中把信息带过黑暗区间。**

## 产品含义

萤火把这一图景落成可运行的束递能力：

- **业务**：关心谁发给谁、载荷是什么、是否送达；
- **网络**：关心接触是否打开、EID 与下一跳如何选定；
- **运维**：关心束状态、保管深度、时间线与选路依据。

今日的三跳拓扑与接触图模式，是通往上述图景的可部署切片：同一套保管—转发—确认语义，从本机多进程，扩展到跨任务、跨天体的真实接触日程。

## 尺度

| 范围 | 怎么看 |
|------|--------|
| **太阳系** | 可部署目标。接触按分钟到十分钟的光时延排；萤火当前切片落在这里。 |
| **银河系** | 语义成立：稀疏驿站、关窗保管、按跳交班、恒星系当区域、跨恒星走锚点。延迟以年计，图和 TTL 要按航迹重做，不是把 2 秒 gossip 搬上旋臂。 |
| **仙女座等河外** | 单程约百万年量级，中间几乎没有可补位驿站。协议还能写「另一个星系区」，但不是能运转的日常网，本阶段不排。 |

有限光速和没有全局同时，在这些尺度上都成立。能铺开的是光锥里还连得上的岛；不是「处处在线」，更不是一张覆盖全宇宙的路由表。

## 不变的原则

无论节点落在地球机房、月球背面中继，还是外行星轨道器上，下列原则保持不变：

1. **断续是常态，连通是窗口**——设计以关窗保管为默认路径，而非异常分支。
2. **逐跳负责，而非端到端幻觉**——每一跳在具备条件时推进，并把责任交给下一保管者。
3. **局部可知即可前进**——不要求全太阳系或全银河瞬时一致；接触图与摘要在相遇时生长。
4. **业务与运维分离**——投递语义对应用保持稳定；度量与时间线对运维保持可见。
5. **市场在协议之上**——节点可以分属不同所有者；投递不绑死在某一家的账单上。见 [`market.md`](./market.md)。

## 一句话

当太阳系各处都有束递节点在跑，人类在深空交换的不再是「此刻能否连上」，而是「这批报文是否已在正确的下一跳手里」——**暗空很长，萤火很短，但一跳一跳，终能相连。**
