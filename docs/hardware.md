# 硬件与性能参考

萤火以 **Kubernetes** 部署在**三台同规格**计算机上：一机一节点、本地盘保管。下文给出星上取向的两类配置——**三台 ARM**、**三台 x86**——对应能支撑的业务并发与保管容量（经验值；上星前在目标板实测）。

射频天线／功放由任务方提供，不在本文范围。`bandwidthBps` 真实限速见 `docs/todo.md`。

## 怎么部署

三台同款机器进同一 K8s 集群，各绑一个角色（lander／orbiter／入口等）。机器规格一致，职责用配置区分，不靠三台买成三种配置。

## 三台 ARM

**单机（×3 相同）：** 4 核 · 4 GB 内存 · 64 GB 盘  

| 业务能力 | 量级 |
|----------|------|
| 并发收发／转发 | 末端约十余路；中继开窗约数十路小报文 |
| 内存中的在途数据 | 约 100～300 MB／节点 |
| 关窗保管（本地卷） | 建议按 8～40 GB／节点做水位，中继偏高以便窗内排空 |

适合低功耗载荷路径；镜像需 ARM 版 `bp-codec`。

## 三台 x86

**单机（×3 相同）：** 8 核 · 16 GB 内存 · 256 GB 盘  

| 业务能力 | 量级 |
|----------|------|
| 并发收发／转发 | 软件侧常可达上百路小报文；实际多被星间链路卡住 |
| 内存中的在途数据 | 约 200～500 MB／节点 |
| 关窗保管（本地卷） | 建议 20～80 GB／节点，入口端可按任务再预留

适合更高算力的星载／加固 x86 路径；现在可用地面三机预演，**不排除以后上星**。

## 选型一句

要省电、盘紧 → **ARM 三机**；要更大并发余量与保管余量 → **x86 三机**。都是「三台同规格 + K8s 三角」，不是无状态三副本打散。
