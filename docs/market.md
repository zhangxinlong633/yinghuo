# 补位商业：中继即利润单元（萤火）

萤火的技术形态是 store-and-forward；商业形态不必是「一家公司拥有整张太阳系网」。补位策略把**每一台中继**做成可计价、可接入、可分成的微节点：不追求独占整条路，只在数据经过自己时收费，再用开放协议和别的所有者互联。本文是愿景与对照，不是报价单，也不是已实现的账本。

一句话：**不建一张由某一家控制的网，而是建一个太空通信市场。** 协议指定公共锚点、开放注册、束自己选路、按跳记账。

## 中继器 = 收费亭

把节点想成太空里的收费亭 + 驿站：不拥有整条接触弧，但保管、转发、加急、缓存都可以标价。收入点（愿景拆解，数量级仅供讨论）：

| 收入点 | 计价 | 谁付 |
|------|------|------|
| 数据转发 | GB 或 Mbps·秒 | 发送方 / 接收方 |
| 存储缓存 | GB·天（关窗保管） | 数据拥有者 |
| 优先级通道 | 加急 / 专线 | 时延敏感任务 |
| 边缘算力 | CPU／GPU·小时 | 预处理、推理 |
| 导航与授时 | 终端·年 | 探测器、殖民地 |
| 能源补给 | kWh | 过路航天器 |
| 数据市场抽成 | 成交额一小部分 | 买卖双方 |
| 冠名／展示 | 时段 | 品牌 |
| AI 运维 | 节点·月或事件·次 | 节点所有者、任务方 |

萤火**已经能看见**的是转发、保管、TTL、以及 Agent 运维入口（MCP + 控制台）。优先级还没有独立队列；算力、授时、能源、广告、按次计费的运维套餐不在账本里。

## 谁拥有，谁分成

节点不归一家。政府／机构骨干可把剩余容量批发；商业星座零售带宽；大学和众筹节点按流量接入；行星本地网关给本地区服务并向过路束收费。

一笔投递的总费用 = 流量 + 存储 + 优先级。路径上各跳按贡献分成；节点所有者拿大头，协议维护与地面站拿小头。节点越多覆盖越好，报价竞争越充分——这是激励，不是已经跑通的智能合约。

行政指定「必须走某国节点」容易垄断。协议指定是：位置关键、容量大、信誉高的节点可登记为**锚点**（地月 L 点、火星轨道、行星网关），接入开放、价格透明、非歧视。其余节点连到锚点做补位。这与萤火的 `backbone`／`edge`、`DTN_REGION` 区门是同一分层：区内叶子连本区骨干，跨区只走门，不把全网图灌进小设备。

## 节点注册 + 选路 + 按跳结算

1. **注册**：符合标准的中继公布 EID、轨道／坐标、接触窗、带宽与存储、价格表、信誉。对应今天的 join + 图摘要，但摘要里还没有价格与信誉字段。
2. **选择**：发送方给目的地、体量、可接受延迟、预算、是否必须经过／避开某节点。网络按价格、时延、容量、可靠性选一条或多条路。今天 CGR 只优化最早到达，不读报价。
3. **按跳结算**：每过一跳记一笔。微支付、积分或联盟账本都是远期；本仓库只有 custody ACK，没有钱。

发送方也可以只定预算和时延，让束在接触图上自己找路——和「不指定完整路径、只指定 dst」的现有 `send` 一致，差的是约束里还没有钱。

## 场景（愿景）

- **殖民地宽带**：本地节点 → 轨道中继 → 行星际骨干 → 地球轨道 → 地面站，月费由各跳分成。
- **探测器回传**：科学数据按 GB 付转发费，沿途保管节点按 GB·天收缓存。
- **边缘推理**：原始图在附近中继上算完只回传结果，省带宽，按算力计费。
- **数据市场**：节点缓存可检索的科学／遥感数据，成交抽成。萤火 inbox 不是交易所。
- **AI 运维**：节点所有者或任务中心用 Agent 盯接触窗、保管深度、CORRUPT／unhealthy、计划热更和选路试算；人类仍在控制台做审批。按托管节点数或处置事件收费。

单节点「数年回收投资」取决于发射批量化、占用率和是否真有过路流量，本文不把某一组人民币数字写成承诺。

## AI 运维

光时长、关窗是常态，驻场值班不划算。把运维面交给 Agent：读状态、解释时间线、建议下一跳、在授权下 reload 计划或发送，异常才叫醒人。

萤火已有分层：业务 API 只见节点名和载荷；网络／运维走 `/api/graph`、`/api/bundles`、控制台；Agent 走 `@yinghuo/mcp`（stdio）和 `mcp:http`（Bearer、只读模式、JSONL 审计）。这是「可托管的运维面」，还不是自动飞控，也没有按节点订阅计费。

收入可以拆成：托管套餐（每节点每月）、值守包（接触开窗／故障唤醒）、诊断包（CORRUPT、选路失败、区门不通）、合规审计日志。创始公司可以卖这层 SaaS，节点仍归别人——开放网络里运维平台和结算层一样，是抽成点而不是锁死 join。

独立节点也可以自己接 MCP，不强制买官方运维；官方认证节点可以把「Agent 可观测 + 人类审批」当成认证条件之一。

## 三件套（尚未做）

| 层 | 作用 | 萤火现状 |
|----|------|----------|
| 投递 | 关窗保管、开窗转发、完整性 | BPv7、custody、SHA-256、副本提升、开机 AUDIT |
| 路由 | 发现路径、避开故障 | CGR／SABR、unhealthy、区域／档位 |
| 运维 | 监督、诊断、授权动作 | 控制台 + MCP；无计费、无自动飞控 |
| 市场 | 注册表、报价、按跳分账、信誉与仲裁 | 无；join token 只挡错网，不是结算身份 |

还需要：统一节点身份（EID 已有雏形）、路由竞价、低手续费结算、多路径、端到端加密（中继只见束不当成明文业务）、频谱／轨道治理（ITU／多边，不是本仓库）。

最小愿景切片：**若干骨干锚点 + 开放注册（join）+ DTN 选路 + 按跳记账**。从地月开始，边建边接入。开放不等于免费，补位不等于让利。

作为能运转、有过路流量的网，目标先放在**太阳系可部署、银河系语义成立**。仙女座等河外单程约百万年，不是本阶段的区配置；尺度说明见 [`vision.md`](./vision.md)。

## 创始层：不垄断节点，占据关键层

别人可以建中继；创始团队的利益靠四层不可替代的工作，而不是堵住接入：

| 层 | 角色 | 收入（愿景） |
|----|------|----------------|
| 协议与标准 | DTN 扩展、路由、结算、身份 | 认证、FRAND 许可 |
| 结算 | 跨节点清算账本 | 每笔协议费／手续费 |
| 初始锚点 | 先占关键接触位（L 点、轨道门） | 转发收入、优先路由、接入背书 |
| 治理与品牌 | 联盟、商标、认证节点 | 会员、品牌溢价 |
| AI 运维平台 | Agent 值守、诊断、审计、热更建议 | 托管订阅、事件费、认证加项 |

组织结构可以拆成三块，避免「开源仓库」和「收费运营」搅在一个法人里：

1. **基金会**：标准、商标、认证、频谱协调对话；理事会给发起方保留席位。
2. **公司**：初始锚点、地面站、结算运维、**AI 运维托管**、技术支持；股权融资与退出走这里。
3. **治理代币／DAO（可选）**：节点与用户投票升级；发起方持有一部分并限时解锁。核心协议变更可设**限时守护否决**，到期必须交还社区，避免永久后门。

抽成只抽协议与清算，不抽走节点该拿的保管／转发大头——节点越多，过路笔数越多，协议费才涨。绕过结算层的闭环网用多边频谱与互操作认证约束，不靠禁止别人发射。

本仓库目前是 **BSD-3-Clause 开源投递栈**，没有基金会、没有账本、没有代币。EID、join、CGR、区门、MCP 是以后结算、锚点和运维套餐要挂上去的钩子，不是已经在抽成。

风险上：节点想绕开协议费 → 结算必须是转发完成的必要条件；专利与开源并行时用 FRAND，避免标准挟持；治理代币被收购 → 质押上限和限时否决要写进章程，而不是写进 bundle 状态机。
