# 动态加入的局部接触图选路

日期：2026-10-01

教学演示。节点通过引导对端动态加入；每台只维护局部接触图，并与邻居交换接触摘要。选路：先按物理坐标丢掉离目的地更远的邻居，再在剩余候选里按预计时延（等待窗口 + 单程光时）选下一跳。运维同时展示坐标视图与时延视图；真正转发只走上述规则。业务载荷仍用 BPv7 CBOR 与现有保管逻辑。集群规模不写死；人工验收时起 10 个进程依次加入。

## 目标

- 新节点只需自己的身份、坐标、端口，以及一个已在网中的引导 URL，即可加入。
- 本机图随摘要交换增长；只知道一部分对端，逐跳向前。
- 控制台按可变规模的网络图与选路对照改版，不再以两段固定接触为主视图。
- 业务层 API 与三层可见性保持：操作页不画图；连接页看图；运维看选路度量。

## 非目标

- 不实现完整 CGR/SABR、Chord/Kademlia DHT、DAG 共识。
- 不做无引导 URL 的零配置发现（仍需知道引导节点地址）。
- 不把保管、转发状态机交给 bplib；摘要通道与 BPv7 ingest 分开。
- 不删除现有三节点静态计划文件；默认改为「可 join 的接触图模式」。
- 不修改 `k8s/`。

## 架构

同一套 Nest 守护进程。启动参数 / 环境变量提供：`NODE_ID`、`EID`、`PORT`、平面坐标 `(x,y)`、可选 `BOOTSTRAP_URL`。无 `BOOTSTRAP_URL` 时本机即为引导岛（第一台）。

```
join(引导 URL)
    → 双方登记种子邻居 + 初始可连接触（或短时引导接触）
    → 引导方返回接触摘要
本地接触图（节点坐标、边、窗口、delayMs、originatedAt、hopCount、直连标记）
    → 窗口内节流与邻居 POST /api/peer/graph 交换摘要
选路：坐标过滤 + 时延最小 → 现有 custody / BPv7 forward / ack
```

运维并排：

- 坐标：本机到目的地的距离、各邻居是否更近。
- 时延：候选上的 `timeUntilOpen(now) + delayMs`。

实际下一跳 = 更近邻居中时延最小者。

## 加入

`POST /api/peer/join`（引导节点）：

请求：`{ nodeId, eid, port, x, y, peerUrl }`（peerUrl 为加入者可达的回调地址）。  
响应：`{ ok, localEid, summary }`，`summary` 为引导方当前接触摘要。

双方：

1. 将对方写入种子 `peers`。
2. 确保存在一条双方之间的接触（种子计划可给默认 cyclic；或 join 时写入「period 内长开」的引导接触，便于摘要先流通）。
3. 加入者合并返回的摘要。

离开 / 崩溃不做优雅 leave（教学简化）：转发失败后选路避开 unhealthy 邻居；摘要过期后听说的边不再参与时延计算。

## 接触摘要

单独 API：`POST /api/peer/graph`，`Content-Type: application/json`。

摘要条目至少包括：

- 节点：`id, eid, x, y`
- 边：`a, b, delayMs, schedule, originatedAt, hopCount`
- 发送方：`from`

合并规则：

- 同一条边保留 `originatedAt` 更新者。
- 接收时 `hopCount += 1`；超过上限（默认 3）丢弃。
- 直连种子边 `hopCount = 0`，不受听说衰减影响。
- 节流：对同一邻居最短间隔（如 2s）内不重发；仅在接触对该邻居打开时发送（引导接触打开时即可）。

不在摘要里携带业务 payload 或 custody。

## 选路

输入：目的节点名（业务），`now`。

1. 目的不在本地图或缺少坐标 → 不转发，保管为 WAITING，运维「目的不在本地图」。
2. 候选 = 本机有 peer URL 的邻居，且图上存在到该邻居的出边。
3. 丢掉 `distance(neighbor, dst) >= distance(me, dst)` 的邻居（欧氏距离，坐标同单位）。
4. 对剩余：代价 = 到该邻居接触的 `timeUntilOpen(now)` + 该边 `delayMs`；取最小。
5. 无候选 → WAITING，图或窗口变化后重试。

选路事件写入束时间线（短句：选中谁、裁掉谁）。

旧静态 `nextHop` 仅在 `CONTACT_PLAN` 指向旧 tri/dual 且未启用图模式时使用。图模式由配置 `DTN_GRAPH_MODE=1` 或默认新计划启用。

## 失败

| 情况 | 行为 |
|------|------|
| 转发 HTTP 失败 | 现有 WAITING + 窗口内重试；该邻居可标 unhealthy 一段时间 |
| 摘要过期 | 不参与时延排序；坐标图上可仍显示为虚线「听说过」 |
| 引导节点不可达 | join 失败，进程可退出或保持单机岛 |
| 全部更近邻居不可用 | WAITING，直到摘要带来新边或邻居恢复 |

## 控制台

顶栏仍分业务 / 网络 / 运维，格局调整如下。

| 页 | 变化 |
|----|------|
| 连接 → 网络图 | 主区域：本机已知节点坐标图；本机高亮；种子/直连实线；仅摘要听说虚线。侧栏：选中边的窗口、delay、新鲜度、hopCount。原两行接触表降为明细。 |
| 运维选路 | 对当前束或试算目的：并排「坐标候选 / 被裁掉」「时延排序」「实际下一跳」。 |
| 操作 | 目的下拉 = 本机图中已知节点（可变）。不嵌入整图。发送/收件箱两栏可保留。 |
| 概览 | 已知节点数、种子邻居数、摘要最大年龄、当前可试算目的数。 |
| 束 | 时间线含选路事件。 |

业务页仍不出现 EID 列表刷屏或 hex；网络图在连接页。

## 测试规模

默认不预设 10 节点表。验收脚本：

1. 起引导节点。
2. 再起 9 个节点，依次 `BOOTSTRAP_URL` 指向引导（或指向已加入者，形成链状加入）。
3. 从第一台业务节点发往最后一台；推进接触窗口直至送达。
4. 杀掉一个非唯一割点的中间节点，确认选路可改走其它更近邻居（种子拓扑需保证坐标上存在替代方向）。

单元测试注入 `now`：过滤、时延排序、摘要合并与 hop 裁剪。

## 验收清单

- join 后双方为种子邻居，图含对方坐标。
- 加入至 10 台后，至少一台的图含非直连的听说边。
- 选路遵守坐标过滤 + 时延最小；运维两列与实际下一跳一致。
- 目的坐标未知时不转发。
- 业务 send/inbox 形状不变；载荷仍为 CBOR。
- 连接页主视图为可变规模坐标图，而非仅两行表。
- 自动化：合并/过滤单测通过；可选 live 脚本 10 节点送达。

## 范围

本规格覆盖：动态 join、摘要扩散、局部接触图选路、控制台网络图与选路对照。完整深空 CGR、无引导发现、副本冗余保管不在本次。
